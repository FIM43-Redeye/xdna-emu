# Phoenix Observable Transaction-ELF `EXEC_DPU` -- Design

**Date:** 2026-07-29

**Status:** Approved for implementation

## Purpose

Expand the proven Phoenix direct `EXEC_DPU` contract from the installed
`nop.elf` command/control proof to an authentic transaction ELF whose
XRT-patched arguments drive observable AIE-array work.

This slice proves the existing mlir-aie `add_one_objFifo_elf` test through the
same pinned normal-XRT, open-driver, vfio-user, unmodified-firmware boundary.
The expected output is the ordered 64-word range `42..=105`.

## Position in the Full Goal

The eventual target includes full ELF/PDI bundling, preemption, lifecycle
recovery, and timing equivalence. Those remain required, but each changes a
different contract and will be closed in a separate proof.

This slice is limited to:

- a transaction ELF containing `.ctrltext` and runtime relocation records;
- a separate xclbin carrying the PDI and kernel metadata;
- normal XRT argument patching;
- direct `EXEC_DPU` firmware dispatch; and
- externally observable array output and command completion.

## Pinned Producer

Use the tracked upstream test:

```text
/home/triple/npu-work/mlir-aie/test/npu-xrt/add_one_objFifo_elf
```

Its C++ host constructs `xrt::elf` and `xrt::module`, passes three buffer
objects through the kernel call, and verifies all 64 output words. Its MLIR
runtime sequence transfers the input to the array, waits for the output DMA,
and exposes the input and output buffers as relocatable transaction-ELF
arguments.

Build both established compiler variants with the existing bridge compiler
path:

```text
mlir-aie/build/test/npu-xrt/add_one_objFifo_elf/chess/
mlir-aie/build/test/npu-xrt/add_one_objFifo_elf/peano/
```

The implementation must pin and check the exact hashes of each generated
`aie.xclbin` and `insts.elf`, plus the shared `test.exe`. It must also record
the mlir-aie commit and the generated artifacts in the evidence tuple. A
missing or mismatched artifact is a hard failure, not permission to rebuild
silently during a KVM proof.

Historical bridge evidence from 2026-07-14 and 2026-07-15 records both Chess
and Peano variants passing on the physical NPU and the emulator. The new build
must be validated again before its hashes become this slice's pinned tuple.

## Selected Approach

Extend the existing Phoenix KVM runner with one explicit mode:

```text
./scripts/phoenix-vfio-user-qemu.sh --run-pinned-elf chess
./scripts/phoenix-vfio-user-qemu.sh --run-pinned-elf peano
```

The mode reuses the existing:

- pinned driver, firmware, guest kernel, QEMU, libvfio-user, register database,
  and XRT checks;
- initramfs construction and dependency discovery;
- normal XDNA XRT plugin;
- vfio-user server and borrowed `DeviceState`;
- bounded guest wait, cleanup, and evidence directory; and
- request, interrupt, and teardown checks.

The guest loads:

```text
amdxdna tdr_timeout_ms=0 force_cmdlist=N
```

It then invokes the unmodified upstream `test.exe` with the pinned
`aie.xclbin` and `insts.elf`. No custom recipe, synthetic relocation table, or
hand-authored transaction ELF is introduced.

## Data Flow

```text
upstream test.exe
  -> xrt::elf / xrt::module builds and patches an instruction BO from insts.elf
  -> normal XRT submits ERT_START_NPU
  -> pinned amdxdna emits direct EXEC_DPU (0x10)
  -> vfio-user publishes the context X2I tail
  -> unmodified Phoenix firmware stages the patched control text
  -> configured PDI and transaction commands run on the shared AIE array
  -> shim S2MM completion reaches firmware
  -> firmware publishes the I2X response and MSI-X
  -> driver fence completes
  -> test.exe reads and verifies 42..=105
  -> context destruction completes
```

Correct output is the relocation oracle. The raw ELF does not know the guest
buffer-object addresses; producing all 64 expected values through freshly
allocated BOs proves that the runtime-patched input and output addresses were
used. The proof does not reimplement XRT's ELF patcher inside the emulator.

## Alternatives Rejected

1. **Custom `xrt-runner` recipe around the upstream ELF.** This replaces the
   upstream host and output oracle without expanding the hardware contract.
2. **Synthetic ELF around the frozen `add_one_using_dma` transaction bytes.**
   This requires inventing relocation metadata already generated by aiebu for
   the upstream ELF test.
3. **Full ELF with embedded PDI.** This is required later, but combines a new
   configuration/loading ABI with the transaction-ELF data-plane proof and
   would obscure which boundary failed.

## Test-Driven Proof Order

1. Record the current unsupported-mode failure for
   `--run-pinned-elf chess`.
2. Build and revalidate `add_one_objFifo_elf` through the existing targeted
   bridge path for both compilers.
3. Pin the resulting artifact hashes.
4. Add the smallest runner and guest-init branches needed to carry and execute
   those artifacts.
5. Run the Chess KVM proof.
6. If the authentic run exposes an emulator behavior gap, capture the exact
   firmware-visible request and add the smallest in-process failing guard
   before changing production behavior.
7. Once Chess passes, run the independently pinned Peano variant.
8. Run the complete local regression gate.

No emulator behavior change is justified merely because a new harness mode is
being added.

## Acceptance

Each compiler variant must prove:

- the guest observed `force_cmdlist=N`;
- normal upstream `test.exe` completed with `PASS!`;
- exactly 64 ordered output checks produced `42..=105`;
- the driver log contains one 160-byte opcode-`0x10` request and its matching
  four-byte response with the same message ID;
- no opcode-`0x18` chained execution request occurred;
- no opcode-`0x0c` `EXECUTE_BUFFER_CF` execution request substituted for the
  ELF path;
- context channel 5 published through management source 37;
- the corresponding MSI-X completion reached the driver;
- matched `DESTROY_CONTEXT` request and response traffic completed; and
- the runner retained the exact artifact and platform tuple.

The slice is complete only when both compiler variants pass, the full library
suite passes, formatting and shell syntax checks pass, the worktree is clean,
and the durable outcome identifies both KVM evidence directories.

## Failure Handling

All tuple mismatches, missing relocatable artifacts, wrong output, wrong
opcode, missing interrupt, timeout, and teardown failures stop the run and
retain evidence under:

```text
build/experiments/phoenix-vfio-user/<run-id>/
```

The existing bounded wait and cleanup remain authoritative. A failure does not
fall back to the emulator plugin, a custom host producer, chained execution,
or a synthetic response.

## Explicitly Out of Scope

- full ELF/PDI bundling and its configuration/loading command form;
- preemption and resume;
- timeout, restart, suspend/resume, and repeated-job recovery;
- timing equivalence;
- multiple simultaneous modules or contexts; and
- older Phoenix firmware versions.

These are deferred slices, not optional goals.
