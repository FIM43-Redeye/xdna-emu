# Phoenix Compute-MM2S Native DMA Fault Proof

**Status:** Implemented and verified on 2026-08-03.

**Target:** Phoenix/NPU1 with pinned unmodified firmware
`amdnpu/1502_00/npu.dev.sbin` version `1.5.5.391`.

**Predecessor:**
[`2026-08-03-phoenix-compute-memory-native-dma-fault-design.md`](2026-08-03-phoenix-compute-memory-native-dma-fault-design.md).

## Boundary

Close the unproven compute-MM2S direction of the signed-firmware asynchronous
error path. This is primarily a characterization and end-to-end regression
slice: the shared DMA-error producer already maps both compute directions and
both per-direction channels. No device-model change is expected.

The architecture remains generic. The physical and KVM proofs use MM2S channel
1 only as an isolated representative tuple; they do not select or privilege
that channel in production behavior.

## Derived facts

- AM025 defines independent compute-memory start queues for S2MM0/1 and
  MM2S0/1. `Start_BD_ID` is derived from the register database.
- aie-rt defines the channel-specific compute-memory events:
  S2MM0/1 are 97/98 and MM2S0/1 are 99/100. All four are enabled members of
  compute-memory `GROUP_ERRORS` by the public error-network initialization.
- The emulator already drains native compute DMA errors and selects those
  generated event constants. The missing fact is an observed MM2S producer and
  its passage through signed firmware and the unchanged driver.

## Representative physical proof

Reuse the existing one-compute-tile `mm2s-egress-depth/burst_8` trace fixture at
runtime tile `(1,2)` (xclbin-local `(0,2)`). Its live data path uses MM2S0, so
MM2S1 is idle and can be faulted without perturbing useful work.

Create a control/fault pair from the same instruction stream:

1. Both streams write `DMA_BD15_5 = 0` immediately before the final TCT,
   explicitly making BD 15 invalid and removing prior-state ambiguity. The
   existing TCT supplies an observation window before trace stop.
2. Only the fault stream then writes `DMA_MM2S_1_Start_Queue = 15`.
3. Trace compute-memory event 100 alongside a live MM2S0 anchor.

Acceptance requires exactly one event-100 observation only in the fault run,
normal completion of both runs, a live anchor in both, and byte-identical
outputs. A mismatch stops the slice; it is evidence to investigate, not a
reason to force the emulator to the expected result.

The initial after-TCT pair completed with no event 100 in either trace. Moving
the same writes before the existing TCT produced exactly one event 100 in the
fault trace and none in the control; both retained the live anchor and produced
the same output hash. A 256-Noop delay attempt timed out and is rejected as
evidence. The accepted receipt is
`build/experiments/phoenix-native-compute-mm2s-dma-error/20260804T001357Z/`.

## Generic regression coverage

Replace the narrow compute-S2MM coordinator test with one compact table over
all four compute DMA channels:

| Direction | Per-direction channel | Generated event |
|---|---:|---:|
| S2MM | 0 | 97 |
| S2MM | 1 | 98 |
| MM2S | 0 | 99 |
| MM2S | 1 | 100 |

Each case starts invalid BD 15 in a fresh engine, asserts
`Error_BD_Invalid`, and observes one toolchain-named event and one async-ring
record. The held error must not republish. Event IDs in the test come from
`xdna-archspec`, not duplicated numeric constants.

This is a characterization test. If it is already green, no production change
is warranted.

## Signed-firmware and driver proof

Extend the existing signed-firmware guard with a fifth registration cycle. It
starts invalid BD 15 on compute MM2S1 and requires one firmware record
`[location=0x0102, module=0, event=100]`, while preserving the native DMA
status assertion and one-shot publication.

Extend `--run-async-error` with workload E generated by the existing generic
register-write patcher. Run E after the row-1 memtile workload D so the prior
cached record cannot match E. Additionally require E's driver timestamp to be
newer than its submission start. The unchanged driver must report:

- `err_code=0x2040304000b`;
- `ex_err_code=0x201`;
- dmesg backtracking to row 2, column 1, module 0, event 100, category 8.

Increase only the test watchdogs needed for one additional signed-firmware
service. Watchdogs remain harness safety bounds and do not become emulated
timing behavior.

## Explicit deferrals

- native compute-core and shim DMA producers;
- other DMA fault causes;
- multiple pending faults, ordering, overflow, and recovery-visible state;
- exact error-production and firmware-service timing.
