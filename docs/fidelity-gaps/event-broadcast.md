# Event-Broadcast Network Gaps

Gaps in the event-broadcast flood topology -- which tiles can broadcast directly
to which neighbours. Surfaced during the #140 timer-sync arc (SP-5c) when the
broadcast network had to carry a *decomposed causal offset*, not merely reach the
right tiles.

| Gap | Model vs hardware | Where | Status / rationale | Obs. |
|-----|-------------------|-------|--------------------|------|
| Shim-row tile-to-tile E/W broadcast edge | model gave **every** tile (incl. the shim row) a direct E/W broadcast edge gated only by block masks; real Phoenix has **no functional tile-to-tile shim-row E/W broadcast** -- a shim-sourced horizontal broadcast detours through the fabric (up to memtile row, across, down), cost `~2*d_v + n*d_h`, not `n*d_h`. Proven on silicon: floods block-forced onto the shim row confine to their source column across 3 kernel variants / 60 clean runs, even with **both** shim broadcast switches' E/W blocks cleared. | `src/device/state/effects.rs` (`broadcast_origin_d`, the `is_shim` E/W guard); `src/device/events/broadcast.rs`; finding: 2026-07-02 shim-row topology (`xdna-emu-priv: research/findings/2026-07-02-sp5c-phase2-shim-row-topology.md`) | **FIXED (2026-07-02, SP-5c pre-flip).** `broadcast_origin_d` now removes the E/W edges from shim tiles; Dijkstra routes shim->memtile (N) -> across (E/W) -> shim (S), yielding the real `2*d_v + n*d_h` detour automatically. Behavior-neutral while `calibrated=false` (reached set unchanged, all `origin_D` 0); guarded by `broadcast_origin_d_shim_source_detours_ew_through_fabric`. Was the one required emu fix before the flip. | confirmed |
| Compute-row vertical hop isotropy | model gave every vertical hop the same delay, 2, both ways: the R3b two-flood perf-counter interval measures only the per-row SUM of the northbound (ch15 from the shim) and southbound (ch14 from the top row) compute-row hops (4), and the even split was an assumption. The timer-reset flood uses only the northbound term, so the model read each compute row's timers 2 lower than the row below. Silicon: a core releasing its own lock and, one bundle later, its south neighbour's stamps the pair +1 apart (south timer minus own; 32 / 32 pairs x 9 runs, rows 2-3 and 3-4), the mirrored pair (own, then the north neighbour's) +1 apart (48 / 48 pairs, 135 runs): with an equal lag both ways the rows' timers agree (the model read +2 / -2). A mid-column ch14 source reads the two rows north of it equal, so the northbound cost is the same on ch14 and ch15. Corroboration with no further constant: a neighbour lock release against the core it frees on the row below (core timers, 3 of 4 stamps exact after the split, the fourth 1 off), receiver S2MM finishes 1 / 2 / 3 rows north of a row-2 source (silicon minus model 2 / 4 / 6 before, 0 after). | `src/device/state/effects.rs` (`HopDelays`, `broadcast_origin_d`); `crates/xdna-archspec/data/skew_constants.json` (`d_v_compute`) | **FIXED (2026-11-14).** A vertical hop between two compute tiles costs 0 northbound and 4 southbound (the R3b sum minus 0); a vertical hop with a shim or memtile end keeps 2, which leaves the memtile against the row-2 core timer as silicon reads it (a memtile North master and the row-2 South slave date one crossing's first word alike). The delay layer is unchanged: the flood is delivered everywhere in one cycle and the hop delays set each module's timer reset value and trace Start stamp, so counts, gap patterns and same-tile offsets do not move; only stamps compared across rows do. Open: the boundary hops (shim to memtile, memtile to compute) are not measured on their own, only the memtile hop minus the memtile offset; the southbound 4 is not measured on its own; the shim's timer is reset by its own generate event at reset value 0, so its reading against the array follows the flood's largest delay, which nothing on silicon pins; the event arrival itself is not delayed (perf counters, trace start windows). | confirmed |
